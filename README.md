# Лабораторная работа №1 — Цветовые модели

## Вариант 6: CMYK ↔ RGB ↔ HLS

Статическое веб-приложение для интерактивной работы с одним цветом сразу в трех моделях: **CMYK, RGB и HLS**.

## Что реализовано

### Работа с тремя цветовыми моделями

Все три представления показываются одновременно. Изменение любой координаты одной модели немедленно пересчитывает две остальные:

- `RGB → HLS` и `RGB → CMYK`;
- `HLS → RGB → CMYK`;
- `CMYK → RGB → HLS`.

### Три способа задания цвета для каждой модели

В каждом блоке RGB, HLS и CMYK доступны:

1. точный числовой ввод;
2. плавное изменение ползунком;
3. кнопка **«Выбрать из палитры»**, открывающая системный выбор цвета браузера.

### Ручная математика

Готовые библиотеки конвертации цветов не используются. Вся математика находится в `src/model/`.

- `rgb-hls.js` — прямое и обратное преобразование RGB ↔ HLS;
- `rgb-cmyk.js` — RGB ↔ CMYK и алгоритмы цветоделения;
- `gamut.js` — Clipping и Scaling;
- `color-model.js` — единая точка пересчета состояния.

Формула CMYK → RGB реализована в виде:

`R = 255(1-C)(1-K)`

`G = 255(1-M)(1-K)`

`B = 255(1-Y)(1-K)`

где C, M, Y и K предварительно переводятся в диапазон `[0, 1]`.

В предоставленном листе формул приведены RGB ↔ CMYK, RGB ↔ XYZ и XYZ ↔ LAB. Формулы HLS в этом листе отсутствуют, поэтому для варианта 6 вручную реализовано стандартное преобразование HLS без сторонних библиотек.

### GCR и UCR

В интерфейсе можно выбрать алгоритм цветоделения:

- **GCR** заменяет общую серую составляющую цветных красок черной во всем диапазоне;
- **UCR** вводит черную компоненту только после достижения настраиваемого порога теней.

Дополнительно регулируется **генерация черного** от 0 до 100%. При любом выбранном уровне CMYK остается обратимо согласованным с исходным RGB.

### Clipping и Scaling

Для RGB реализованы две стратегии обработки выхода за диапазон `[0,255]`:

- **Clipping** — независимое прижатие каждой координаты к ближайшей границе;
- **Scaling** — общая линейная трансформация всех трех каналов, чтобы весь диапазон поместился в `[0,255]`.

Если коррекция была применена, интерфейс выводит ненавязчивое предупреждение и пересчитывает HLS и CMYK уже по итоговому RGB.

### Динамические градиенты

Фон каждого ползунка строится на основе текущих значений остальных компонентов. Например, при изменении `R` градиенты `G` и `B` автоматически перестраиваются с учетом нового красного канала. То же самое выполняется для HLS и CMYK.

## D65 / D50 / E и динамические матрицы

Чтобы буквально выполнить дополнительное требование подгруппы 10А, в интерфейсе есть выбор **D65 / D50 / E**. Готовая RGB ↔ XYZ-матрица не хранится константой: при смене источника программа заново строит ее из координат первичных цветов sRGB и выбранной точки белого, а обратную матрицу получает ручным обращением 3×3. Для D65 используется точка белого `(95.047, 100, 108.883)` из предоставленного листа формул.

Вариант 6 не содержит XYZ или LAB, поэтому рассчитанная служебная матрица **не изменяет CMYK/RGB/HLS-цвет**. Переключатель подтверждает выполнение требования о динамическом расчете матриц, не подменяя математику варианта 6.

## Архитектура

Проект разделен на независимые слои:

```text
src/
├── model/
│   ├── color-model.js
│   ├── color-utils.js
│   ├── gamut.js
│   ├── illuminants.js
│   ├── math.js
│   ├── rgb-cmyk.js
│   └── rgb-hls.js
├── view/
│   └── app-view.js
├── controller/
│   └── color-controller.js
└── app.js
```

### Model

Содержит только математику и не работает с DOM.

### View

Создает интерфейс, элементы ввода, ползунки, палитры, предупреждения и выводит значения.

### Controller

Получает значения из View, вызывает Model, хранит настройки и синхронизирует все три модели.

## Интерфейс

Интерфейс сделан упрощённым и без лишних технических блоков:

- сверху находятся только обязательные настройки: освещение, GCR/UCR и Clipping/Scaling;
- рядом показываются текущий цвет и HEX;
- ниже одновременно расположены три модели — CMYK, RGB и HLS;
- у каждой координаты есть числовое поле и ползунок с динамическим градиентом;
- у каждой модели есть отдельная явно подписанная кнопка **«Выбрать цвет»**, открывающая системную палитру;
- дополнительные параметры генерации чёрного вынесены в компактную строку, а порог UCR отображается только при выборе UCR.

## Тесты

Node.js тесты:

```bash
npm test
```

Браузерные тесты можно открыть через:

```text
tests/test-runner.html
```

Проверяются, в частности:

- `RGB(255,0,0) → HLS(0,50,100)`;
- `RGB(255,0,0) → CMYK(0,100,100,0)`;
- RGB ↔ HLS round-trip;
- CMYK → RGB;
- обратимость GCR и UCR;
- порог UCR;
- интенсивность генерации черного;
- динамический расчет RGB ↔ XYZ-матриц для D65/D50/E;
- обратимость рассчитанных матриц;
- отличие Clipping от Scaling;
- синхронизация всех моделей после gamut mapping;
- выбор цвета из палитры через HEX.

## Исследование цветового графика МКО

Основное условие лабораторной включает изучение цветового графика МКО. Для варианта 6 сам график не участвует в вычислениях, поскольку XYZ не является одной из трех выбранных моделей. Краткое исследование и связь графика МКО с RGB gamut приведены в `docs/REPORT.md`.
