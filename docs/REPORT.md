# Сопроводительная документация

## Лабораторная работа №1. Цветовые модели

**Вариант 6:** CMYK ↔ RGB ↔ HLS.

## 1. Цель работы

Изучить представление цвета в моделях RGB, CMYK и HLS, вручную реализовать взаимные преобразования и создать интерактивное веб-приложение, синхронно отображающее один цвет во всех трех моделях.

## 2. Состав приложения

Пользователь одновременно видит RGB, HLS и CMYK. Для каждой модели доступны числовые поля, ползунки и отдельная кнопка выбора цвета из системной палитры. Любое изменение автоматически становится источником нового состояния и пересчитывает две остальные модели.

## 3. RGB ↔ HLS

Используется нормированный RGB: `r,g,b ∈ [0,1]`. Вычисляются `max`, `min`, `Δ=max-min`.

Светлота:

`L = (max + min) / 2`.

Если `Δ = 0`, цвет ахроматический: `H=0`, `S=0`.

Иначе насыщенность:

`S = Δ / (1 - |2L - 1|)`.

Тон определяется по каналу, равному `max`, и нормализуется в диапазон `[0,360)`.

Для обратного преобразования используются:

`C = (1 - |2L - 1|)S`,

`X = C(1 - |(H/60 mod 2) - 1|)`,

`m = L - C/2`.

После выбора сектора оттенка к промежуточным RGB-компонентам прибавляется `m`, затем значения масштабируются на 255.

## 4. RGB ↔ CMYK

В предоставленном листе формул для обратного преобразования используется:

`R = 255(1-C)(1-K)`,

`G = 255(1-M)(1-K)`,

`B = 255(1-Y)(1-K)`.

Для RGB → CMYK сначала строятся исходные цветные компоненты `C0=1-R/255`, `M0=1-G/255`, `Y0=1-B/255`, после чего выполняется выбранный алгоритм генерации K.

## 5. GCR

Нейтральная составляющая определяется как `N=min(C0,M0,Y0)`. В GCR она может заменяться черным по всему диапазону. Пользователь регулирует долю замены параметром генерации черного.

После выбора `K` итоговые компоненты вычисляются так, чтобы сохранить обратимость:

`C=(C0-K)/(1-K)`,

`M=(M0-K)/(1-K)`,

`Y=(Y0-K)/(1-K)`.

## 6. UCR

UCR использует тот же принцип замены общей нейтральной составляющей, но вводит K только после заданного порога теней. Поэтому в светлых и средних областях черная краска не появляется, а в глубоких тенях постепенно заменяет общую часть CMY.

## 7. Clipping и Scaling

Clipping независимо ограничивает R, G, B диапазоном 0…255.

Scaling использует общую линейную трансформацию. Для исходных значений определяется:

`low=min(0,R,G,B)`,

`high=max(255,R,G,B)`.

Затем каждый канал преобразуется:

`v'=(v-low)·255/(high-low)`.

После любой коррекции HLS и CMYK рассчитываются заново по итоговому RGB, поэтому три отображаемых модели всегда относятся к одному фактическому цвету.

## 8. Динамические градиенты

Для каждого ползунка программа формирует набор промежуточных значений изменяемого канала. Остальные координаты остаются текущими. Каждая промежуточная точка вручную переводится в RGB, после чего на основе полученных цветов строится CSS-градиент.

## 9. Архитектура

Model содержит только математические операции. View отвечает только за интерфейс. Controller получает пользовательские действия, вызывает Model и передает новое состояние во View.

## 10. D65, D50 и E

В интерфейс добавлен выбор D65, D50 и E согласно дополнительному требованию подгруппы 10А. Для каждого источника RGB↔XYZ-матрица строится программно на лету из координат первичных цветов sRGB и выбранной точки белого. Для D65 берется точка белого `(95.047, 100, 108.883)`, указанная в предоставленном листе формул. Готовые матрицы в рабочем коде не хранятся. Обратная XYZ↔RGB-матрица вычисляется ручным обращением матрицы 3×3.

Поскольку вариант 6 непосредственно содержит только CMYK, RGB и HLS, служебная XYZ-матрица не входит в цепочку преобразований текущего цвета и смена источника не должна менять CMYK/RGB/HLS-координаты.

## 11. Исследование цветового графика МКО

Цветовой график МКО CIE xy описывает видимые человеком цветности независимо от яркости. Координаты получают из XYZ:

`x=X/(X+Y+Z)`, `y=Y/(X+Y+Z)`, `z=1-x-y`.

Треугольник первичных цветов RGB занимает только часть области видимых цветностей, поэтому RGB имеет ограниченный gamut. В варианте 6 график МКО не используется как вычислительная модель, но его изучение объясняет, почему разные цветовые пространства имеют различные области представимых цветов.

## 12. Автоматическое тестирование

В проекте предусмотрены Node.js и браузерные микро-тесты. Контрольный красный цвет должен давать:

`RGB(255,0,0) → HLS(0°,50%,100%)`,

`RGB(255,0,0) → CMYK(0%,100%,100%,0%)`.

Дополнительно проверяются обратимость преобразований, GCR/UCR, обработка диапазонов и выбор цвета через HEX.

## 13. Вывод

Разработано независимое статическое веб-приложение для варианта 6, в котором преобразования выполнены вручную, все три модели синхронизируются автоматически, реализованы GCR/UCR, две gamut-стратегии, динамические градиенты, трехслойная архитектура и автоматические тесты.
